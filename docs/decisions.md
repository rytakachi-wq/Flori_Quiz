## 追加の決定(2026-10-08)

- 得点:1問5点。5問だけ遊んだ回の満点は25点。(「20問(4回分)の満点100点」は、あとで総合得点に置きかえた。「追加の決定(その5)」を見る)
- 難しさの段階:カウンター0〜2が段階1、3〜5が段階2、6〜8が段階3、9以上が段階4。
- フロリの表情:顔だけの4種を、手を振る全身画像の画面部分にはめ込んで使う(`assets/flori/wave_*.png`)。表紙は手を振る全身、出題中は本とペン、正解は笑顔、不正解は><、段階が上がった問題は驚き、結果は にっこり。
- 技術:HTML・CSS・JavaScript のみ(ビルドなし、外部ライブラリなし)。ブラウザで動く。
- 公開:GitHub Pages(`rytakachi-wq/Flori_Quiz` の `main` ブランチの直下)。URL は https://rytakachi-wq.github.io/Flori_Quiz/ 。更新は `main` に push するだけで、1〜2分で反映される。リポジトリは公開(誰でも中身を見られる)。
- カウンターの引き継ぎ:ページを開いたまま続けて遊ぶときだけ引き継ぐ。保存はせず、画面を閉じたら0に戻る。

## 追加の決定(その2:機能の追加)

利用者の依頼で、scheme.md の「今回は作らない」に入れていたものの一部を、今回の範囲に入れた。

- 問題数:ふつうの問題は35問(段階1〜3が各10問、段階4が5問)+オニ問題5問、合計40問。1回(5問)は、35問から難しさのカウンターで選ぶ。段階の問題が足りないときは、いちばん近い段階の問題で補う(同じ近さなら下の段階を先に使う)。20問(4回分)が終わったら、出した問題の記録とカウンターを最初に戻す。
- 保存の範囲(scheme.md の「最高得点のみ」から拡大):成績として、次を端末内に保存する。名前などの個人情報は入れない。ログインは不要。
  - 5問の最高得点、遊んだ回数、答えた問題数と正解数(せいかい率)
  - (20問(4回分)の記録は、のちに総合得点に置きかえて、やめた。「追加の決定(その5)」を見る)
  - 出会った問題・正解したことのある問題の番号(成績に「出会った問題 ○ / 35問」「正解した問題 ○ / 35問」と出すため)。問題が増えたら、全体の数もそれに合わせる(いまある問題だけを数える)。問題の番号をつけなおしたときは、数がずれることがある。
  - カウンターと出した問題は、保存しない。
- 表紙:「はじめる」「せいせき」「せってい」の順にボタンを置く。
  - せいせき:上の成績を見せる。
  - せってい:BGMと効果音の大きさ(0〜100)を変えられる(「追加の決定(その4:音)」を見る)。記録を消す機能は、まだ作っていない。
- 表紙のすみのフロリ:5回押すと、フロリが「すごいね」などと言って、オニ問題5問に挑戦できる(「やめておく」も選べる)。
- オニ問題:段階5。決まった順に5問(o01〜o05)。難しさの調整はなく、成績にも最高得点にも入れない。結果画面に、5問の得点だけを出す。
- 問題を解いている画面に「やめる」ボタン:押すと確認が出て、やめると表紙に戻る。その回の結果は残さず、その回で出た問題とカウンターも、はじめる前に戻す。

## 追加の決定(その4:音)

- BGMは場面ごとに1曲:表紙・せいせき・せってい=Slime Time、ふつうの問題=Ticketless、オニ問題=Swan Lake Theme、結果発表=Swan Lake Theme(曲が3つなので、オニ問題と結果は同じ。最初は表紙とオニ問題が逆だったが、利用者の依頼で入れかえた)。
- 効果音:ボタンをおしたとき=決定ボタン、せいかい=ドアチャイム、ふせいかい=クイズ不正解。
- せってい:BGMと効果音の大きさを、0〜100のつまみで変えられる(0で音が出ない)。大きさは端末内に保存する(個人情報ではない)。はじめは、BGM 70、効果音 80。
- ブラウザの決まりで、画面を1回さわるまでは音が出ない。表紙には「画面をクリックすると、おんがくが ながれるよ」と出し、さわったら消す。BGMが止まっていたら、画面をさわるたびに流しなおす。ほかのタブに切りかえても、BGMは止めない(止めると、見えている画面でも止まる場合があったため)。
- 音量の決め方(音量を変えすぎると、聞こえなくなったり大きすぎたりしたため直した):
  - つまみ(0〜100)を、0 dB〜-30 dB に均等にわりあてる(耳は、音量の倍率ではなく、デシベルで大きさを感じるため)。0 のときは、BGMを止めずに音量だけを0にする(止めたり流したりをくり返すと、流れなくなることがあった)。
  - 測ったところ、BGM3曲は平均の大きさが -10.8〜-13.5 dB と大きく、曲ごとに差があり、効果音(-23〜-26 dB)より大きかった。そこで、BGMを曲ごとに、つまみ100のとき -19 dB にそろえ(最初は -16 dB だったが、BGMが大きいという声で、3 dB 下げた)、小さい効果音(ボタン音・不正解)はもち上げた(ボタン音は、小さいという声で、1.7倍から2.4倍に上げた)(`src/audio.js` の BGM_GAIN と boost)。曲を入れかえたら、測りなおす。
- 問題を解いているときも、画面上の「せってい」ボタンから、音の大きさを変えられる(表紙のせっていと、同じ大きさを使う)。開いているあいだは、数字キーで回答できない。
- 音のファイルは `assets/audio/`。曲の利用条件(クレジット表記の要否など)は未確認なので、利用者が確認する(`assets/audio/README.md`)。

## 追加の決定(その5:総合得点)

「4回(20問)の記録が100点満点」と「全40問(ふつう35問+オニ5問)」がくいちがうため、100点満点を、全問題の総合得点に1本化した。

- 総合得点(100点満点):ふつうの問題35問で95点、オニ問題5問で5点(1問1点)。
  - ふつうの問題:一度でも正解した問題の数 × 95 ÷ 35(四捨五入)。
  - オニ問題:一度でも正解した問題1問につき1点。
  - 一度正解した問題は、ずっと残る(何度正解しても、同じ問題は1回ぶん)。
- 成績の満点は、いつでも「100点満点」と見せる。ふつうの問題だけでは95点までしか取れないので、「まだ何かある」と、うっすら感じさせる。成績の画面には、オニ問題のことや、40問という数は、出さない(出会った問題・正解した問題は「○ / 35問」)。
- 「20問(4回分)の記録」(今の20問、20問の最高、20問を終えた回数)は、やめた。4回遊ぶと、難しさのカウンターと出した問題の記録を、最初に戻す動きは、そのまま。
- オニ問題の結果:「遊んだ回数」「解いた問題」「正解率」「最高得点(1回)」には入れない。はじめて正解した問題の分だけ、総合得点に入る(結果画面に「総合得点が○点ふえたヨ」と出す)。
- せってい画面には、オニ問題や得点のことを出さない(音の大きさだけ)。
- 保存するもの:正解したことのあるオニ問題の番号(`oniRight`)を足した。
